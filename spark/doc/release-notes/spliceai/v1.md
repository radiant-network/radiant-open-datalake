# Changelog — spliceai contract MAJOR 1

All notable changes to the `spliceai` data contract, lineage `1.x`, will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this contract
adheres to the lineage rule of [SJRA-1546]: MINOR is bumped in place for an additive change carried by
schema evolution, a breaking change is a new MAJOR with its own changelog file.

|---|---|
| Table | `spliceai_v1` — derived from `table_prefix: spliceai` + MAJOR 1 (catalog and database are deploy-time config) |
| Normalizer | [`SpliceAi_v1.scala`][normalizer] |
| Raw input | `raw_spliceai` — `<raw-storage>/spliceai/{{VERSION}}/spliceai_scores.raw.*.hg38.vcf.gz`, VCF, flattened INFO |
| Row filter | `max_score.ds >= 0.2` — Illumina's high-recall delta-score cutoff, applied per variant-gene pair |

## [Unreleased]

## [1.1] - 2026-09-25

This MINOR changes which rows are published, not the schema — every column of `1.0` is still present
with the same name and type, so the table needs no migration and Iceberg schema evolution is not
involved. It is recorded as a MINOR because consumers need a version signal for a change in row
population; the lineage rule's usual MINOR trigger (an additive column carried by schema evolution)
does not apply here.

### Changed

- **A minimum delta score of `0.2` is now required to publish a row.** Rows whose `max_score.ds` is
  below `0.2` — or null — are dropped in `transformSingle`, before the `locus_hash` is computed.
- The cutoff is **inclusive**: `0.2` is the first score kept, not the first dropped.
- The cutoff is applied **per variant-gene pair**, which is the grain of this table. A variant
  annotated against several genes is published only for the genes that clear the cutoff, and leaves the
  table entirely when none of them do.
- Rationale: Illumina defines the delta score of a variant as "the maximum of (DS_AG, DS_AL, DS_DG,
  DS_DL)", which "ranges from 0 to 1 and can be interpreted as the probability of the variant being
  splice-altering", and characterises **0.2 (high recall)**, 0.5 (recommended) and 0.8 (high precision)
  as the cutoffs described in the paper — [Illumina/SpliceAI][spliceai-readme], [Jaganathan et al.,
  *Cell* 2019][spliceai-paper]. The precomputed release scores every position in the transcriptome, so
  the overwhelming majority of rows sit at or near `0`.
- The filter reads `max_score.ds` rather than re-deriving a maximum over the four `ds_*` columns, so
  there is one definition of the delta score shared with the published `max_score` struct.

### Notes for consumers

- Expect a large drop in row count against `1.0`. The four `ds_*` and `dp_*` columns are unchanged for
  the rows that remain, so a query filtering on a **higher** threshold (0.5, 0.8) keeps working
  unchanged; a query that relied on sub-`0.2` rows being present will now return nothing for them.
- Published branches from earlier runs are independent Iceberg refs and are not rewritten — only runs
  from this lineage onward carry the cutoff.

## [1.0] - 2026-08-07

### Added

- Initial contract. The `normalized_spliceai` dataset family, narrowed to MAJOR 1, is published to
  table `spliceai_v1` from the SpliceAI precomputed delta-score VCFs named by the `--version` launch
  argument. Illumina distributes the scores as two VCFs (SNV and indel) with identical schemas; the raw
  glob (`spliceai_scores.raw.*.hg38.vcf.gz`) unions both into one table, one row per variant-gene pair.
- Locus columns `chromosome`, `start`, `end`, `reference`, `alternate`.
- `locus_hash` — `sha2(concat_ws('-', chromosome, start, reference, alternate), 256)` as 64-char
  lowercase hex, the platform variant join key. Radiant's `variant_lookup` resolves surrogate variant
  ids through it (SJRA-1811); it matches the portal occurrence side and the StarRocks generated column,
  and is computed by the shared `normalized.Locus` helper so the expression cannot drift between
  sources. `chromosome` is canonicalised to the hg38 spelling first (`MT` -> `M`), so the same
  mitochondrial variant reaches the same key whatever the source VCF calls the contig.
- `allele` and `symbol` from the `SpliceAI` INFO field.
- Delta scores `ds_ag`, `ds_al`, `ds_dg`, `ds_dl` (acceptor/donor gain/loss, doubles) and their
  positions `dp_ag`, `dp_al`, `dp_dg`, `dp_dl` (ints), split out of the pipe-delimited `SpliceAI` field.
- `max_score` — a struct `{ ds, type }` holding the strongest of the four delta scores for the row and
  the event(s) that reached it (ties keep every tied event; a zero score yields a null `type`).
