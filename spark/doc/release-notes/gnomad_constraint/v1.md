# Changelog — gnomad_constraint contract MAJOR 1

All notable changes to the `gnomad_constraint` data contract, lineage `1.x`, will be documented in this
file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this contract
adheres to the lineage rule of [SJRA-1546]: MINOR is bumped in place for an additive change carried by
schema evolution, a breaking change is a new MAJOR with its own changelog file.

## [1.0] - 2026-11-02

### Added

- Initial contract, implemented against gnomAD **v4.1.2**
  (`release/4.1.2/constraint/gnomad.v4.1.2.constraint_metrics.tsv.bgz`). The v4.1.1 file has the identical
  header. Field meanings are in gnomAD's
  [`gnomad.v4.1.1.gene_constraint_ht_README.md`][gnomad-readme].
- One row per **Ensembl** transcript (`transcript` starts with `ENST`). RefSeq transcripts (`NM_`, `XM_`,
  ...) are not published: in the source they have no chromosome, start or end, and the table is
  partitioned and repartitioned on the locus.
- Column naming: every source column is published with its dots replaced by underscores, case kept
  (`lof.oe_ci.upper` → `lof_oe_ci_upper`, `lof.pLI` → `lof_pLI`). The only renames are
  `chromosome` (the `chr` prefix is removed: `chr19` → `19`), `start_position` → `start`,
  `end_position` → `end` and `gene` → `symbol`.
- Locus and identity: `chromosome`, `start`, `end`, `symbol`, `gene_id`, `transcript`, `transcript_version`,
  `transcript_type`, `transcript_level`, `canonical`, `mane_select`, `cds_length`, `num_coding_exons`.
- Gene quality: `gene_quality_metrics_exome_prop_bp_AN90`, `gene_quality_metrics_exome_mean_AS_MQ`,
  `gene_quality_metrics_exome_prop_segdup`, `gene_quality_metrics_exome_prop_LCR`, `gene_flags`
  (`array<string>`), `constraint_flags` (`array<string>`).
- For each of `syn`, `mis`, `lof_hc_lc` (high + low confidence pLoF) and `lof` (high confidence pLoF):
  `<c>_mu`, `<c>_possible`, `<c>_obs`, `<c>_exp`, `<c>_oe`, `<c>_z_raw`, `<c>_z_score`, `<c>_oe_ci_lower`,
  `<c>_oe_ci_upper`, and per genetic ancestry group (`global`, `afr`, `amr`, `eas`, `nfe`, `sas`)
  `<c>_gen_anc_obs_<g>` (`array<int>`) and `<c>_gen_anc_exp_<g>` (`array<double>`). The array elements can
  be null. The downsampling levels that index these arrays are a Hail Table global; the TSV does not carry
  them.
- `lof_hc_lc` and `lof` only: `<c>_pLI`, `<c>_pNull`, `<c>_pRec`.
- `lof` only: `lof_oe_ci_upper_rank`, `lof_oe_ci_upper_bin_percentile`, `lof_oe_ci_upper_bin_decile`,
  `lof_oe_ci_upper_bin_sextile`.

### Changed

- This contract replaces, in place, a first implementation against gnomAD v2.1.1
  (`gnomad.v2.1.1.lof_metrics.by_gene.txt.bgz`, flat columns such as `pLI` and `oe_lof_upper`). No consumer
  read that version, so it is not kept as a separate MAJOR.

### Removed

- Not contract-managed prior to this MAJOR: `enriched.Genes` still reads the pre-contract
  `normalized_gnomad_constraint_v2_1_1` table (kept as a frozen legacy input — see the comment in
  `EtlConfiguration.scala` — until `Genes` is migrated to read this branch-qualified contract table).
