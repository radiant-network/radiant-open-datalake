## [1.0] - 2026-08-06

### Added

- Initial contract. The `normalized_gnomad_cnv` dataset family, narrowed to MAJOR 1, is published to
  table `gnomad_cnv_v1`, one row per VCF record, from the gnomAD release named by the `--version`
  launch argument.
- Implemented against gnomAD **v4.1** — the exome CNV callset (`gnomad.v4.1.cnv.all.vcf.gz`). 
- Locus columns `chromosome`, `start`, `end`, `reference`, `alternate`. A CNV record carries `N` as its
  reference and a symbolic `<DEL>` / `<DUP>` as its alternate; the interval is what identifies it.
- `name` — the release's own variant id (e.g. `variant_is_80_2__DEL`)
- CNV descriptors `svtype` (`DEL` or `DUP`) and `svlen`.
- Global **sample** counts, as gnomAD defines them: `sc`, the individuals carrying the variant; `sn`,
  the individuals with a non-null genotype at it; `sf`, the proportion `sc / sn`. A CNV VCF has no
  AC/AF/AN — frequency is over samples, not alleles.
- Only the records the release marked `PASS` are published.

### Removed

- The exome CNV VCF carries about 112 INFO fields: `SC`, `SN` and `SF` for ten genetic ancestry groups,
  each also split by sex (XX/XY). Only the three global counts above are published.
- `Genes`, `N_EXN_VAR`, `N_INT_VAR`, `POSMIN`, `POSMAX`, `ENDMIN` and `ENDMAX` are not published: no
  consumer asks for them.
- `qual` is not published: the QUAL column is `.` on every record.
- `filters` is not published: once the `FAIL` records are dropped the column holds `PASS` on every row.
