## [1.0] - 2026-08-07

### Added

- Initial contract. The `normalized_hpo_genes` dataset family, narrowed to MAJOR 1, is published to table
  `hpo_genes_v1`, one row per gene→phenotype association from the versioned `genes_to_phenotype.txt`
  release named by the `--version` launch argument.
- Columns (renamed from the release file `ncbi_gene_id, gene_symbol, hpo_id, hpo_name, frequency, disease_id`):
  - `entrez_gene_id` (`long`, from `ncbi_gene_id`)
  - `symbol` (from `gene_symbol`)
  - `hpo_term_id` (from `hpo_id`, e.g. `HP:0000007`)
  - `hpo_term_name` (from `hpo_name`)
  - `frequency` (nullable — `-` in the source becomes null)
  - `disease_id` (e.g. `OMIM:243400`)

### Notes

- **Published per Iceberg branch, `main` stays empty (standard WAP, same as the other contracts).** Consumers
  name the `dataset_version` branch — reading `main` returns zero rows.
- Distinct from the legacy `hpo_gene_set` table (`HPOGeneSet`, plain `OverWrite`, sourced from an
  unversioned `/hpo/genes_to_phenotype.txt`), which still feeds `enriched.Genes` from `main`. This contract
  is the versioned successor; rewiring `enriched.Genes.withHPO` to read the `hpo_genes_v1` version branch is a
  follow-up and is intentionally out of scope here.
- **Schema is the current HPO release format** (6 columns, header row). The legacy job parses a pre-2021
  9-column headerless layout; that mapping is stale for current data. `entrez_gene_id`, `hpo_term_id` and
  `hpo_term_name` are named to match what `enriched.Genes.withHPO` joins on, so the eventual rewire is a
  branch change only, not a schema change.
