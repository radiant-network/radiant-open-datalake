# Changelog — gnomad_sv contract MAJOR 1

All notable changes to the `gnomad_sv` data contract, lineage `1.x`, will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this contract
adheres to the lineage rule of [SJRA-1546]: MINOR is bumped in place for an additive change carried by
schema evolution, a breaking change is a new MAJOR with its own changelog file.

## [1.0] - 2026-08-07

### Added

- Initial contract. The `normalized_gnomad_sv` dataset family, narrowed to MAJOR 1, is published to
  table `gnomad_sv_v1`, one row per PASS VCF record, from the gnomAD release named by the
  `--version` launch argument.
- Implemented against gnomAD **v4.1** — `gnomad.v4.1.sv.sites.vcf.gz`, the full release (genomes).
- Locus columns `chromosome`, `start`, `end`, `reference`, `alternate`
- `name` — the gnomAD SV identifier, e.g. `gnomAD-SV_v3_DEL_chr22_1a2b3c4d`. The `v3` in those
  identifiers is not a version mismatch: the v4.1 SV callset comes from the v3 genomes, republished
  under 4.1.
- `svtype` — DEL, DUP, INS, INV, CPX, CTX or CNV.
- Global frequencies `ac`, `an`, `af`, and the genotype counts `n_het`, `n_homalt`, `n_bi_genos`.

### Removed

- The gnomAD SV VCF carries 619 INFO fields — `AC`/`AN`/`AF` per genetic ancestry group and per sex,
  the `PREDICTED_*` functional annotations, the calling evidence and complex-interval descriptors.
  Only the thirteen columns above are published. Adding one later is a MINOR bump carried by schema
  evolution; removing one would be a new MAJOR.
- Records that did not pass the source filters are **not published**: the table holds only the calls
  gnomAD marks PASS. Recovering a filtered record means reading the raw VCF.
- `filters` is not published either — it would carry the same value on every row
- `qual` is not published. Unlike the gnomAD joint sites VCF, whose QUAL column is empty, the SV file
  does carry a caller score — it is left out because we don't intend to use it
