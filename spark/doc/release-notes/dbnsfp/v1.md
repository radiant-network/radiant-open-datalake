All notable changes to the `dbnsfp` data contract, lineage `1.x`, will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this contract
adheres to the lineage rule of [SJRA-1546]: MINOR is bumped in place for an additive change carried by
schema evolution, a breaking change is a new MAJOR with its own changelog file.

## [1.0] - 2026-08-11

### Added

- Initial contract. The `normalized_dbnsfp` dataset family, narrowed to MAJOR 1, is published to
  table `dbnsfp_v1` from the per-chromosome dbNSFP variant tables
  (`dbNSFP<version>_variant.chr*.gz`) of the release named by the `--version` launch argument.
- The archive is a manual source: the download DAG stream-unzips the dbNSFP `.zip` (URL supplied at
  trigger time) and lands the per-chromosome members in the versioned raw prefix.
- **Transcript-specific grain.** dbNSFP packs the predictions for every overlapping Ensembl
  transcript into `;`-delimited fields; the job explodes on `Ensembl_transcriptid` to one row per
  (variant, transcript) and aligns each predictor's value to that transcript, so the scores are
  directly joinable.
- Locus columns renamed from the dbNSFP header: `#chr` → `chromosome`, `position_1-based` → `start`,
  `ref` → `reference`, `alt` → `alternate`; plus `aaref` and the per-transcript
  `symbol`, `ensembl_gene_id`, `ensembl_protein_id`, `ensembl_transcript_id`, `VEP_canonical`,
  `cds_strand`.
- The full dbNSFP predictor set, typed: `*_score` / `*_rankscore` as `double`, `*_pred` as string,
  `.` normalized to null (SIFT, PolyPhen-2 HDIV/HVAR, FATHMM, CADD, DANN, REVEL, LRT, MutationAssessor,
  MutationTaster, PROVEAN, VEST4, MetaSVM/MetaLR/MetaRNN, M-CAP, MPC, MVP, PrimateAI, DEOGEN2,
  BayesDel, ClinPred, LIST-S2, fathmm-MKL/-XF, Eigen, GenoCanyon, fitCons, LINSIGHT, bStatistic,
  phyloP/phastCons conservation, GERP++), `Interpro_domain`, and `GTEx_V8_gene` / `GTEx_V8_tissue`
  as arrays.
- `locus` (`chromosome-start-reference-alternate`) and `locus_hash` (`sha256(locus)` hex) — the
  platform variant join key, matching the portal occurrence side and the StarRocks
  `sha2(concat_ws('-', …), 256)`.
